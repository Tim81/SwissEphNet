## Area provenance

Every regeneration (reference or local) replaces the *entire* set of
baseline-*.tsv files -- scripts/regenerate-baseline.ps1 has no per-area or
per-row logic (see its own comments). What actually distinguishes a
"package-2.8.0.2" area from a "local-<sha>" one below is not which script
invocation last touched the file on disk, it is whether the file's current
*content* is still byte-identical to what that original 2.8.0.2 package run
produced, verified area by area, not assumed:

- `package-2.8.0.2` means: this area's committed content is confirmed
  byte-identical to the original reference-mode run recorded in the eight
  fields at the top of this file. It proves "unchanged since 2.08" -- an
  actual oracle, because the reference package predates any local code this
  repo might have since patched.
- `local-<short-sha>` means: this area's committed content was last produced
  by `-FromLocal` at the given commit (see "Local regenerations" below for
  what changed and why). It proves only "unchanged since the day it was
  written" -- a regression net against future drift, not an oracle against
  2.08, because local code authored the content in the first place.

## Local regenerations

The eight fields above describe the original reference-mode generation run
(SwissEphNet 2.8.0.2 NuGet package) and are kept verbatim as a historical
record: BaselineVerify's assembly-identity check
(Tools/BaselineVerify/Program.cs, CheckAssemblyIdentity) compares the
currently-running build against exactly SwissEphModuleVersionId and
SwissEphAssemblySha256 above to confirm local mode never accidentally
compiles to the same bytes as the reference package. Do not edit those two
fields when regenerating from local code.
